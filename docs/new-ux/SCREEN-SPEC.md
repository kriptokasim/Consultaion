# Consultaion New UX - Screen-by-Screen Specification

## Homepage
Top links: The report, How it works, Your keys. One main Run a question action. Large editorial serif headline. Short explanation. Primary Put it to the panel action. Sample question shortcuts. Then a finished-run report preview with verdict, confidence, agreement, clash and next actions. Explain fan-out, critique, scored verdict and chamber. Trust section covers BYOK, encrypted keys, auditable records and routed keys. Finish with one primary CTA.

## First Run
Headline asks the user to put a difficult question to a panel. Explain that multiple models answer separately and can then argue. Composer is the main object. Returning view pins the active run with status, round, question, challenger and rejoin action. Examples are real runs with verdict, confidence and mode; selecting one loads its question for editing.

## App Shell
Run list title Your runs. Filters: All, Live, Closed, Needs me. Row includes status, mode, time, question and compact metadata. Empty state gives one Ask your first question action. Error state explains runs are safe, gives the failure context, retry, status page and reference. Offline state says the run continues server-side. Mobile bottom navigation: Runs, Ask, Panel, You.

## Run Workspace
Composer copy: Put a question to a panel. Supporting line: choose how they should answer it. Mode chips: Arena, Debate, Compare, Oracle, RedTeam. Then question field and panel summary. Active run shows question, verdict status, confidence, verdict note, full report action, share, panel rows and divergence. Model rows show model identity, event-derived state and response text.

## Decision Report
Header has back, Share and Export. Document has dateline, question title, facts, verdict, confidence, agreement, divergence claims, positions, judge outcomes, risks, three numbered actions, provenance and integrity note. Report remains paper inside the app. Follow-up action may appear at the bottom.

## Marketing Pages
Demo is a recorded deterministic run with play and skip-to-verdict actions. Model registry shows model identity, use-case note, median, cost and judges' pick with a caveat that judges' pick is a historical debate-result measure, not a universal ranking. Pricing starts with beta, then team and enterprise; enterprise claims must match shipped features.
